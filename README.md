# chip8_core

Ядро эмулятора **CHIP-8** на Rust. Библиотека предоставляет память, регистры, стек, таймеры, клавиатуру и видеобуфер — всё, что нужно для запуска ROM-файлов. Отрисовка, звук и ввод со стороны пользователя остаются на стороне приложения, которое использует это ядро.

## Возможности

- Полный цикл **fetch → decode → execute**.
- 4 КБ памяти с предзагруженным шрифтом (0x000–0x04F) и загрузкой ROM по адресу `0x200`.
- 16 регистров общего назначения `V0`–`VF`, индексный регистр `I`, счётчик команд `PC`.
- Стек вызовов на 16 уровней.
- Таймеры задержки и звука.
- Видеобуфер и детекция коллизий для `DXYN`.
- Состояние 16 клавиш клавиатуры.
- Опциональный режим **SUPER-CHIP** (экран 128×64 и расширенная семантика некоторых инструкций).
- Ядро не выполняет ввод-вывод и не зависит от способа отрисовки — его можно встроить в любой фронтенд (терминал, SDL, WASM и т.д.).

## Требования

- Rust 2024 edition (rustc 1.85+).
- Зависимость: [`rand`](https://crates.io/crates/rand) `0.10.3` — используется инструкцией `CXNN`.

## Сборка и тесты

```sh
cargo build
cargo test
```

С включённым режимом SUPER-CHIP:

```sh
cargo build --features SUPER-CHIP
cargo test --features SUPER-CHIP
```

## Использование

```rust
use chip8_core::{Emulator, SCREEN_HEIGHT, SCREEN_WIDTH};

fn main() -> std::io::Result<()> {
    let rom = std::fs::read("roms/ibm_logo.ch8")?;

    let mut emu = Emulator::new();
    emu.load_rom(&rom);

    // Нажатие/отпускание клавиши с индексом 0x0..0xF
    emu.keypress(0x1, true);
    emu.keypress(0x1, false);

    // ~60 Гц: таймеры и отрисовка; ~500–1000 Гц: инструкции
    for _frame in 0..60 {
        for _ in 0..10 {
            emu.tick();
        }
        emu.tick_timers();

        // framebuffer: SCREEN_WIDTH * SCREEN_HEIGHT пикселей, построчно
        let display = emu.get_display();
        assert_eq!(display.len(), SCREEN_WIDTH * SCREEN_HEIGHT);

        if emu.is_sound_playing() {
            // ... включить звук ...
        }
    }

    Ok(())
}
```

### Публичное API

| Метод / константа | Описание |
| --- | --- |
| `Emulator::new()` | Создаёт эмулятор, заполняет память шрифтом, выставляет `PC = 0x200`. |
| `load_rom(&[u8])` | Копирует ROM в память начиная с `0x200`. |
| `tick()` | Выполняет одну инструкцию. |
| `tick_timers()` | Уменьшает таймеры задержки и звука на 1; вызывать с частотой 60 Гц. |
| `get_display() -> &[bool]` | Возвращает видеобуфер (построчно, длина `SCREEN_WIDTH * SCREEN_HEIGHT`). |
| `keypress(idx, pressed)` | Устанавливает состояние клавиши `idx` (0–15). |
| `is_sound_playing() -> bool` | `true`, пока таймер звука больше нуля. |
| `SCREEN_WIDTH`, `SCREEN_HEIGHT` | Размер экрана: 64×32 или 128×64 в режиме SUPER-CHIP. |

## Поддерживаемые инструкции

| Опкод | Мнемоника | Описание |
| --- | --- | --- |
| `0NNN` | SYS | Игнорируется (NOP). |
| `00E0` | CLS | Очистить экран. |
| `00EE` | RET | Возврат из подпрограммы. |
| `1NNN` | JP addr | Переход на `NNN`. |
| `2NNN` | CALL addr | Вызов подпрограммы по адресу `NNN`. |
| `3XNN` | SE Vx, byte | Пропустить следующую инструкцию, если `Vx == NN`. |
| `4XNN` | SNE Vx, byte | Пропустить следующую инструкцию, если `Vx != NN`. |
| `5XY0` | SE Vx, Vy | Пропустить следующую инструкцию, если `Vx == Vy`. |
| `6XNN` | LD Vx, byte | `Vx = NN`. |
| `7XNN` | ADD Vx, byte | `Vx += NN` без переноса. |
| `8XY0` | LD Vx, Vy | `Vx = Vy`. |
| `8XY1` | OR | `Vx = Vx OR Vy`. |
| `8XY2` | AND | `Vx = Vx AND Vy`. |
| `8XY3` | XOR | `Vx = Vx XOR Vy`. |
| `8XY4` | ADD | `Vx += Vy`, `VF` — флаг переноса. |
| `8XY5` | SUB | `Vx -= Vy`, `VF` — флаг отсутствия заёма. |
| `8XY6` | SHR | Сдвиг `Vx` вправо, младший бит в `VF`. |
| `8XY7` | SUBN | `Vx = Vy - Vx`, `VF` — флаг отсутствия заёма. |
| `8XYE` | SHL | Сдвиг `Vx` влево, старший бит в `VF`. |
| `9XY0` | SNE Vx, Vy | Пропустить следующую инструкцию, если `Vx != Vy`. |
| `ANNN` | LD I, addr | `I = NNN`. |
| `BNNN` | JP V0, addr | `PC = NNN + V0`; в режиме SUPER-CHIP — `PC = NNN + Vx`. |
| `CXNN` | RND Vx, byte | `Vx = random() & NN`. |
| `DXYN` | DRW Vx, Vy, nibble | Рисует спрайт, инвертируя пиксели; `VF` — коллизия. |
| `EX9E` | SKP Vx | Пропустить следующую инструкцию, если клавиша `Vx` нажата. |
| `EXA1` | SKNP Vx | Пропустить следующую инструкцию, если клавиша `Vx` не нажата. |
| `FX07` | LD Vx, DT | `Vx = DT`. |
| `FX0A` | LD Vx, K | Ожидает нажатия клавиши и записывает её номер в `Vx`. |
| `FX15` | LD DT, Vx | `DT = Vx`. |
| `FX18` | LD ST, Vx | `ST = Vx`. |
| `FX1E` | ADD I, Vx | Установка `I` из `Vx` (см. примечания). |
| `FX29` | LD F, Vx | `I` указывает на спрайт цифры `Vx`. |
| `FX33` | BCD | Записывает BCD-представление `Vx` в `I`, `I+1`, `I+2`. |
| `FX55` | LD [I], V0..Vx | Сохраняет регистры в память; в базовом режиме `I += X + 1`. |
| `FX65` | LD V0..Vx, [I] | Загружает регистры из памяти; в базовом режиме `I += X + 1`. |

## Режим SUPER-CHIP

Функциональность включается Cargo-фичей:

```sh
cargo build --features SUPER-CHIP
```

Что меняется:

- экран становится 128×64 (`SCREEN_WIDTH` / `SCREEN_HEIGHT`);
- `BNNN` прибавляет `Vx` вместо `V0`;
- `FX55` / `FX65` не изменяют `I` после выполнения (поведение SUPER-CHIP).

## Примечания и ограничения

- Это **ядро**, а не готовая программа: рендеринг, аудио, обработка клавиш и цикл частот реализуются в потребляющем приложении.
- `DXYN` заворачивает начальные координаты по размеру экрана, но не переносит пиксели, выходящие за границы: рисование обрезается по краям.
- `FX1E` в текущей реализации присваивает `I = Vx`, а не прибавляет `Vx` к `I`.
- Неизвестный опкод вызывает панику через `unimplemented!`.
